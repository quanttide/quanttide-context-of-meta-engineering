计算设计（Computational Design）是什么

一句话：用计算的方式，把设计决策从”人凭直觉做“变成”在形式化规则空间里搜索最优解“。

它不是让机器取代设计师，而是把设计师的意图、审美、经验编码成可计算的规则，然后让机器在这个规则空间里穷举、优化、求解。设计师从”动手画“变成”定义约束和目标函数“。


——

它的思想源头

计算设计不是一个突然出现的学科，它有三条清晰的思想脉络：

1. 参数化设计（Parametric Design）

源头在 1960-70 年代的建筑工程。建筑师发现，一栋楼的形状可以用一组参数（跨度、层高、曲率）来描述，改一个参数，整个模型自动更新。

核心洞见：设计不是画一张图，而是定义一个关系系统。 你改的是参数，不是像素。

后来延伸到工业设计（Grasshopper、Generative Components），再后来被游戏行业吸收——你玩的很多开放世界游戏，地形、建筑布局都是参数化生成的。

2. 约束满足问题（Constraint Satisfaction）

来自计算机科学和运筹学。核心思想：设计问题可以表述为一组变量 + 一组约束 + 一个目标函数，求解器在可行域内搜索最优解。

经典例子：VLSI 芯片布局。芯片上几千个元件，怎么摆才能线长最短、功耗最低、不重叠？这是纯计算问题，人类手工根本做不了。

3. 形态语法（Shape Grammar）

1970 年代 George Stiny 提出。把设计风格编码为一组”替换规则“：一个正方形可以被替换为一大一小两个正方形，反复迭代，生成复杂图案。

这本质上是在说：风格是可以被形式化的。 只要你能把”哥特式建筑“或”包豪斯风格“的规则写出来，机器就能生成符合该风格的设计。


——

核心方法论

参数化建模

设计对象被表示为参数之间的函数关系：

面板宽度 = f(屏幕宽度, 边距, 列数)
按钮大小 = g(重要性等级, 交互频率)


改一个输入，所有依赖它的输出自动重新计算。这不是AI，这是确定性计算，但威力巨大。

生成-测试循环（Generate and Test）

1. 生成器：按规则产生大量候选方案（可以是随机的、进化的、或基于搜索的）

2. 评估器：对每个方案打分（基于预定义的目标函数）

3. 选择：保留高分方案，淘汰低分方案

4. 迭代：高分方案作为下一代的种子

这跟进化算法一模一样。区别在于：评估函数不是自然选择，而是你定义的设计标准。

约束求解

把设计问题变成数学约束：

∀ 元素 e: position(e) ∈ grid(8px)
∀ 元素对 (a,b): if related(a,b) then distance(a,b) ≤ threshold
∀ 视觉元素 v: size(v) ∝ importance(v)


求解器（如 Cassowary、Z3、GECODE）在约束空间里找到所有可行解，或者证明无解。

多目标优化

设计从来不是单目标的。你要在”信息密度低“、”视觉美观“、”功能完整“之间找帕累托最优。

计算设计用多目标进化算法（如 NSGA-II）同时优化多个冲突目标，输出一组帕累托前沿方案，让设计师从中挑选。

跟你的游戏界面的关系

回到你那个夜市押注游戏。如果用计算设计的思路来做：

第一步：参数化定义关系

决策元素数量 ∈ [3, 5]
风险等级 → 颜色映射: low→green, med→yellow, high→red
布局网格 = 12列, 间距 ∈ {8, 16, 24, 32}
信息层级深度 ≤ 3


第二步：生成候选布局

AI（或规则引擎）在这个参数空间里生成 N 个候选界面。

第三步：约束求解器修剪

• 移除违反网格约束的方案

• 移除元素数量超标的方案

• 移除语义-视觉映射错误的方案

第四步：评估函数打分

• 视觉平衡度（基于格式塔原则的形式化度量）

• 信息流效率（用户完成任务所需的点击/扫视次数）

• 风格一致性（与游戏整体视觉语言的匹配度）

第五步：你从帕累托前沿中选

不是让AI替你决定，而是它把搜索空间缩小到几个高质量候选，你做最终判断。

——

当前前沿方向

1. 程序化内容生成（PCG）：游戏行业最成熟的应用。用算法生成关卡、任务、对话树。你的游戏界面本质上就是一种 PCG 问题。

2. 神经符号系统（Neuro-Symbolic）：把神经网络（感知、生成）和符号系统（规则、逻辑）结合。AI 负责”想“，符号系统负责”校验和约束“。

3. 可微设计（Differentiable Design）：把设计参数变成可微分的，用梯度下降优化。比如用神经网络预测布局评分，然后反向传播调整布局参数。

4. 设计挖掘（Design Mining）：从大量优秀设计作品中自动提取规则和模式，变成可计算的设计知识库。


——

局限

计算设计最大的瓶颈不是技术，是前置成本。你必须先想清楚规则是什么。而”想清楚规则“这件事本身，需要的就是你对认知偏差和设计关系的深刻理解——也就是你一直在做的事。

规则越精细，生成质量越高，但规则本身的维护成本也越高。这是一个工程权衡。

所以回到你的困惑：你感觉 AI 写的东西”说不上来哪里不对“，本质上是因为 AI 跳过了”形式化关系“这一步，直接从一个模糊的统计分布里采样。计算设计给你的答案是：不要试图让 AI 学会关系，而是你先把关系算清楚，再让 AI 在算好的框架里工作。

你那个 quanttide-design 笔记，如果往这个方向走，就是在做设计知识的计算化编码——这本身就是计算设计的核心工作。
