# 本体论驱动的智能体

> 工作论文。由对话记录整理而成：论证与判断保持原样、未加料，口吻由对话体改为论文体。

## 摘要

大模型证明了拟合能力可以很强，但它不知道自己知道什么、为什么知道、什么时候该更新。本文主张：**智能的瓶颈不是拟合能力，而是结构能力**。据此提出一条工程路线——把「理解」变成结构化建模：先建本体（世界的存在论骨架），再让智能在结构上运行，推理沿结构推导而不在向量空间里做模式匹配。本文给出可运行的五层架构、从工业界可执行本体（Palantir）可吸收的工程模式，并如实列出这条路引入的新问题。

## 一、引言：能拟合，但不知道自己知道什么

传统路线（包括大模型）的问题是同一个：能拟合，但不知道自己知道什么。知识是隐式的、弥散的，散在权重里；说不清"我知道什么、不知道什么"，也说不清推理怎么来的。

本文要做的恰好相反：**先建结构，再让智能在结构上运行**。

- 本体：世界的存在论骨架——有哪些东西、它们什么关系
- 模型：本体在具体情境下的实例化——当前世界状态
- 推理：在结构上做推导，而不是在向量空间里做模式匹配

这本质上是神经符号路线的一种工程化表达：用本体给智能一个可解释的认知底座。

## 二、核心主张：结构先于拟合

这条路在赌一件事：**智能的瓶颈不是拟合能力，而是结构能力**。

大模型证明了拟合可以很强，但它不知道自己知道什么、为什么知道、什么时候该更新。本体论驱动的路线，是在给智能一个**可生长、可解释、可约束**的认知骨架。

如果这个赌注成立，那么建模能力就是下一代智能系统的核心竞争力——不是调参，不是堆数据，而是把世界结构化成可推理的形式。

## 三、五层架构

一个可运行的本体论驱动智能体，按五层搭。

**1. 本体层**：定义领域里存在什么。类（Agent、Action、Object、Goal、Belief）、属性（hasGoal、locatedAt、causes）、公理（"任何 Action 都有 Agent""Belief 不能同时为真和假"）。

**2. 实例层**：当前世界状态的本体实例化。每个时刻的"世界模型"就是本体的一个模型；图数据库存，节点是实例、边是关系；支持增删改查，相当于智能体的工作记忆。

**3. 推理层**：在结构上做推导。规则推理（SWRL、SHACL、Datalog）、描述逻辑推理（分类与一致性检查）、图算法（路径、中心性、社区发现）、概率推理（贝叶斯网络 + 本体）。

**4. 学习层**：从数据中自动扩展本体。本体学习（从文本/日志抽取新类新关系）、概念格构建（FCA 从对象—属性矩阵生成层级）、嵌入（把本体节点映射到向量空间供神经网络使用）。这层让本体不是死的手写规则，而是能生长的。

**5. 行动层**：智能体基于结构做决策。规划（在状态空间上搜索）、查询（查询当前世界模型）、生成（把推理结果翻译成自然语言或动作）。

## 四、可执行本体：从工业界借什么

工业界已有可执行本体的工程证明（以 Palantir 为代表）：它把"存在什么、能做什么、谁可以做"全部结构化，让人和 AI 在同一张决策图上行动。它与本文路线在底层信念上一致——结构先于拟合、本体不是静态描述而是可操作的、人和智能体共享同一套语义；区别在目的因：前者从"做什么决策"收敛，本文从"存在什么结构"展开。

可吸收的工程骨架是**四元组 + 三层**：

- 四元组：Object（实体或事件的 schema）、Property（对象的特征）、Link（两个对象类型之间关系的 schema）、**Action（对对象、属性、关系的一组修改，含前置条件与副作用）**。Action 是关键差异——传统本体只读，可执行本体的 Action 有副作用，绑定了前置条件、执行逻辑与后置触发链。
- 三层：Language（表达有什么、怎么连、能做什么）、Engine（让表达成为可扩展的读写运行状态——实时物化、双向同步）、Toolchain（把能力交给开发者与智能体，并纳入治理）。

三点具体吸收建议：

1. **本体层引入 Action**，绑定前置条件、执行逻辑、后置触发链
2. **实例层改为实时物化 + 双向同步**：对象是底层数据源的实时投影，Action 执行后写回源系统——否则"推理结果"与"世界状态改变"之间是断裂的
3. **推理层区分两类 Function**：派生属性计算（声明式、血缘可追溯）与复杂业务逻辑（图灵完备代码、可解释性退化）。本文路线只吸收第一类，对第二类保持警惕或建立可解释性审计

**要警惕的语义断层**：一旦引入图灵完备代码，可解释性就退化为普通函数调用。哪些逻辑留在本体结构内（可推理）、哪些允许下沉为黑盒，这条边界决定了系统是"可解释的认知架构"还是"带本体的工程系统"。

吸收策略一句话：**用工业界的"四元组 + 三层 + Action 执行 + 双向写回"做工程骨架，用自己的"公理化推理 + 可追溯性"做认知内核。**

## 五、设计原则

1. **本体要小、要长**：别一上来就建大本体，让它随任务生长
2. **推理要可解释**：每条推理结果都能追溯——这是相对纯神经方法的核心优势
3. **实例与本体分离**：本体是 schema，实例是数据，分开存、分开更新
4. **与 LLM 互补，不替代**：LLM 做抽取、翻译、生成；本体做结构、约束、推理
5. **从任务反推本体**：先问"智能体要完成什么任务"，再问"完成它需要知道什么"，最后才建对应的类和关系

## 六、案例：让工具描述自己

已有一个最小实证——元工程正在开发的范畴分析工具（`qtcloud-meta` 的 CLI）。它把本体写成 YAML（概念、边、公理），再用这些本体做分析；而它**自己的模块结构**也被写成了一份本体，由工具自己分析自己。

它证明了这条路线里最要紧的三件事：

1. **输入模型够通用**：不改一行代码，加一份 YAML 就能分析一个新范畴——范畴由使用者定义，工具不硬编码
2. **工具能吃自己的狗粮**：它分析业务本体的那套方法，同样能分析它自己——可信度不是靠说的，是靠跑出来的
3. **本体与实现会漂移，而且能被抓住**：代码改了、本体没跟上，分析报告就会显出差异。这是"活文档"与"死注释"的分界

这个案例的规模很小，但它是可复算的：本体文件、分析命令、报告都在仓库里。

## 七、代价与新问题

每一个深刻的解决方案，都会引入一批新的、甚至更根本的问题。这条路至少带来十类：

1. **本体的冷启动与维护**：建一个能用的本体极其昂贵；世界在变，改一处可能引发连锁反应
2. **表达力与可判定性的根本张力**：强表达力意味着推理不可判定，可判定意味着表达力受限——这是数学上的硬约束，不是工程能绕过的
3. **非标准模型**：一阶理论无法唯一确定无限世界，智能体可能推理出你根本没想过的结构
4. **可解释性的退化**：一旦允许黑盒函数下沉，可追溯推理的优势就在关键环节失效
5. **语义断层与集成噩梦**：不同来源的本体如何对齐，至今没有完美解法
6. **概率与不确定性的缺失**：经典本体论是确定性的，而真实世界充满不确定性；补上概率会让推理复杂度爆炸
7. **本体论承诺的哲学陷阱**：你选了哪些类与关系，就等于承诺了世界上有这些东西——而"谁来决定该包含什么"是规范性问题，不是技术问题
8. **计算复杂度与实时性**：复杂推理可能只能离线批处理
9. **结构可能成为新的牢笼**：本体越精确，行为空间越受限，可能牺牲智能的涌现能力
10. **评估与验证的困难**：怎么知道本体"对"？没有标准答案；本体若有缺陷，推理再严谨也是错的

## 八、结论

核心赌注：**结构能力是智能的瓶颈，而不是拟合能力**。
核心代价：必须在表达力、可判定性、可解释性、不确定性、灵活性之间做一系列取舍——没有银弹，只有权衡。

最深一层的新问题是：当你用本体去建模世界时，本体本身的本体论地位又成了问题——**你用什么来建模"建模"本身**？这会带来自我指涉。

但这不意味着这条路走不通。它意味着要建的不仅是一个系统，而是一个**知道自己局限、能反思自身结构**的系统。这才是真正的形式化智能。
