# 格式章程应归类为文档工程（而非叙事工程）

> 决议日期：2026-08-26

## 来源

- 原文：《量潮科技文档格式章程》（格式工程分类决议所针对的规范对象）
- 仓库：[quanttide/quanttide-bylaw-of-business-entity](https://github.com/quanttide/quanttide-bylaw-of-business-entity)
- 当前路径：`docs/format.md`
- 备注：该路径即将变更，引用时请以仓库内实际位置为准

这份章程的规范对象不是"写什么"或"如何讲故事"，而是"怎么排"——它系统规定了 Markdown 语法要素（标题层级、列表标记、表格对齐、代码块标注、加粗使用场景等）的**使用规则与约束边界**。其目标是"降低阅读成本，消除因格式混乱导致的信息损耗"，属于典型的**呈现层（presentation layer）规范**。

## 与量潮叙事工程的分界

量潮科技自身对"叙事工程"有明确定义：其叙事工程档案关注写作内容的**流程管理**（想法→提纲→草稿→文章四个阶段）与**情境化设计**（"把用户放在一个情境中，让他们的每个选择都有可感知的结果"）。而这份章程完全不涉及内容创作的叙事结构、信息架构或用户情境，仅约束格式元素的**使用频次与语法规则**，二者属于不同层面。

## 与文档工程学科的吻合

从学科定义看，文档工程（Document Engineering）的核心正是将文档的**内容/结构与呈现特性**（如格式、排版）分离，建立可复用的文档模型与规范。这份章程所做的事——为 Markdown 文档建立统一的格式标准、定义元素使用边界、甚至将 AI 作为"格式执行工具"——完全符合文档工程"以文档为中心"的规范化目标。

## 结论

若将叙事工程比作"导演决定镜头语言和故事节奏"，文档工程则是"制片方规定字幕字体与片尾格式"。这份章程属于后者：它是保障叙事工程得以顺畅运行的**基础设施规范**，但其本身并不处理叙事问题。
