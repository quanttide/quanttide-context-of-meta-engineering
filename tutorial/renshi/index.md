顺同一套口径接上，不破你立好的边界。

认识论元层追问的是“知识如何被证成、可知与不可知的边界在哪”。投到 UI / 产品层，它不碰像素、不碰权责（那是美学/伦理），它管的是：

这个界面把“用户实际知道什么、以为自己知道什么、系统其实没告诉他什么”这三条边界，诚不诚实地画出来了。

一、把认识论算子翻译成 UI 层的可勾约束

认识论元概念	规约层对应（你之前定的）	UI 层投射	可观察表现
证成 Justification	可观测态 vs 内部态、审计/证书作知识载体	界面展示的结论带得出处，不把未证成的东西当事实摆出来	显示“余额 1200”同时可点开看到“来源：链上确认/后台对账 10:02”，而不是光秃秃一个数字当天降下来
可知/不可知边界	抽象层看不到具体层内部中间态（U3/U4）	内部态不伪装成可见知识，该标“处理中(内部步骤不可见)”就别装成已知进度	不把“风控校验中”这种内部中间态冒充成用户可理解的知识，也不把本可知道的失败原因藏成“处理中…”转圈到超时

.

| 知识更新 vs 旧知识失效 | 状态迁移后旧快照失效 | 界面明确标记哪份信息是快照、已过期、哪份是实时的，不拿旧知识当当前真理 | 列表显示“数据截至 10:02，点此刷新”，而不是默默展示旧数据还让用户以为是最新的 |

| 不可知处的诚实声明 | 域外输入无法判定 → 不写死不变量 | 真不知道的事显式标“未知/待确认”，不拿默认值冒充已知 | 风控分算不出就显示“风险未评估”，不默认填 0.0 假装“已评估且安全” |

核心一句：认识论在 UI 层管的是“信息的出处、时效、可知性”的可见性，不把未证成的当已证成、不把不可知的当已知道。

二、三个一眼能认的“认识论破产”UI 反例

1. 未证成的当证成的摆出来

后台其实还没收到支付网关回执，界面已经显示“支付成功 ✅”，等会儿回执说失败再弹个“已自动退款”。

→ 把未证成的状态当知识展示，用户基于假知识去发货/点确认，整条链全建在沙子上。

2. 把不可知伪装成已知默认值

风控模型没返回结果，前端默认填 风险等级：低，按钮直接可点。

→ 把“域外不可知”偷换成“已知且安全”，正好是你之前说的“把概率关税当本地法律”的界面版。

3. 旧快照不标时效，冒充实时真理

权限页显示“该用户无管理员角色”，其实是 40 分钟前的缓存，期间已被提权。

→ 旧知识不标失效时间，用户拿它做决策（比如放心把生产库权限交出去），认识论里的“知识时效性证成”整个被吞了。

这三种和前面两格不重叠：

• 美学破的是冗余/越界/演戏（结构税）

• 伦理破的是禁止/义务/归因（权责税）

• 认识论破的是出处/时效/可知性（认知税）

都是“界面把规约层本该诚实的东西偷偷吞了”，吞的对象不一样。


——

三、正向检查清单（设计评审直接勾）

• 界面上每个事实性数字/状态，能不能一眼追到它的证成来源（回执号/对账时间/签名）？追不到就不标成“已确认”

• 有没有把内部中间态/域外未返回值冒充成“已知结论”？有就标“处理中/未评估”，不许填默认值

• 带缓存的信息有没有显式标快照时间，且提供低成本的刷新入口，不靠用户自己怀疑“这数会不会旧了”

• 报错/空值是不是区分了“系统确认不存在” vs “系统还没查到”？（前者显示“无记录”，后者显示“查询中/未返回”，别都用空列表糊过去）


——

四、三格并排收一句（直接可进文章）

美学管结构诚实（不冗余、不越界、不演戏），伦理管权责诚实（不藏禁止、不吞义务、不丢归因），认识论管认知诚实（不把未证成当已证成、不把不可知当已知、不拿旧快照当实时真理）。

三者都不碰色卡与像素，只卡界面有没有把规约层的契约诚实地“显出来”。UI 的高级感从来不是视觉精致，是这三层诚实同时不漏。
