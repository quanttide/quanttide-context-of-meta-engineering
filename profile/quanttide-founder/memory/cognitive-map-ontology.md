这份文档在说什么

你的记忆仓库（memory仓）里有三个集：default（日常）、work（工作）、fiction（小说创作）。每个集都有一份 index.ttl，里面记录了你所有的思考条目，以及它们之间的关联。

这份文档是从这三份文件中提炼出来的底层骨架——不是你在想什么，而是你怎么想的。

结论先给出：三份文件是同一套结构的三个变体，不是三套不同的体系。


——

一、骨架：你思考的固定结构

不管什么语境，你的思考都沿着一条链展开：

情境  →  办法  →  归宿


位置	回答的问题	日常 / 工作中的类名	创作中的类名
情境	什么引发了它	触发点	创作困境
办法	怎么应对	方法	创作方法
归宿	办法服务于什么	价值	创作动机

日常和工作集在这条链上多出了中间环节和附属类别，创作集则精简为纯链条。详见下文。


——

二、三个集的全貌

default（日常）与 work（工作）

六个类，结构最完整：

触发点  →  情绪  →  方法  →  价值
                        ↑
                     表达（不参与链，独立类）
                        ↑
              价值  →  排除的形态（反向边界）


类	存在论定位	说明
触发点	情境层	引发思考的外部或内部事件
情绪	中间层	情境唤起的情绪反应；是情境到办法之间的必经环节
方法	应对层	你用来应对情境的具体做法
表达	附属类	关于”如何把这个东西说出来“的思考，不参与因果链
价值	归宿层	方法最终服务的方向或原则
排除的形态	反向边界	某条价值明确拒绝的做法——定义”不要什么“

fiction（小说创作）

三个类，链条精简：

创作困境  →  创作方法  →  创作动机


没有情绪、没有表达、没有排除。在创作语境下，困境直接催生方法，中间不经过情绪层。


——

三、四条关系：骨架之间的连接

三集共用同一套关系语义，只是起点和终点的类名随集变化：

关系	从 → 到	含义
触发	触发点 → 情绪	情境唤起情绪
应对	触发点/情绪 → 方法	用某个办法应对
服务于	方法 → 价值/创作动机	办法最终指向什么
排除	价值 → 排除的形态	这条价值排掉什么做法

串起来：

触发点  ──触发──>  情绪  ──应对──>  方法  ──服务于──>  价值  ──排除──>  排除的形态


fiction 集中没有情绪节点，所以 创作困境 ──应对──> 创作方法，链条缩短一截。


——

四、条目上的属性

每个条目（实例）携带四项元数据：

属性	作用
file	出自哪份档案
group	方法档案内的二级分组（仅方法类使用）
quote	原文摘录——当条目没有独立标题、只出现在某句话中时，用此字段记原话
seeAlso	参见其他条目


——

五、载体与命名

• 每个集一份 index.ttl，本体（类+关系）与实例（具体条目）同住一份文件

• 各自有独立命名空间：urn:quanttide-memory:<集名>:profile:

• 类和关系用 Turtle 语法声明，条目作为实例挂载在对应类下


——

六、三集之间的关系

维度	说明
类名	随集的主题替换（触发点/创作困境/创作动机等）
关系语义	三集完全一致——四条关系的含义不变
结构完整性	fiction 缺少情绪、表达、排除三个类；default 与 work 完整
本质判断	不是三套本体，是同一副骨架的三个实例

差异的意义：fiction 集缺少情绪层，说明在创作语境下，你的思考不经过情绪这个中间环节。这不是数据缺失，是实在本身在不同语境中激活不同范畴的体现。


——

七、这份骨架对你意味着什么

1. 你的思考有统一的底层结构。 日常、工作、创作——表面内容不同，骨架相同。

2. 情绪是日常/工作中不可或缺的环节。 情境不直接跳到办法，中间必须经过情绪。这是你认知的一个结构性特征。

3. 价值不只是”要什么“，还包含”不要什么“。 排除的形态是骨架的一部分，不是附属品。

4. 创作是精简模式。 去掉情绪和表达后，链条更直接——困境直接催生方法。

5. AI 加载这份骨架，就获得了你的思考方式。 不需要学每条具体想法，只需要按这个结构填入新情境。
