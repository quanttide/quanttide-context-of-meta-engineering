# 认知地图本体

从 memory 仓三个集的 `index.ttl` 提炼（default / fiction / work）。三份文件描述的是同一副骨架，各自在语境里换了类名。

## 存在什么

条目按类归位，三个集共用的位置有三格：

| 位置 | default | work | fiction |
|:--|:--|:--|:--|
| 情境：什么引发了它 | 触发点 | 触发点 | 创作困境 |
| 办法：怎么应对 | 方法 | 方法 | 创作方法 |
| 归宿：办法服务于什么 | 价值 | 价值 | 创作动机 |

default 与 work 在这三格之间还夹着一格——**情绪**：情境不直接接到办法，先唤起情绪。另有两个类不参与这条链：**表达**（表达类的条目）、**排除的形态**（价值排掉的那类做法）。

`default` 与 `work` 各六个类：触发点、情绪、方法、表达、价值、排除的形态。
`fiction` 三个类：创作困境、创作方法、创作动机。

## 彼此什么关系

四条有向关系，语义三集一致：

| 关系 | 从 | 到 | 含义 |
|:--|:--|:--|:--|
| 触发 | 触发点 | 情绪 | 情境唤起情绪 |
| 应对 | 情境（触发点或情绪） | 方法 | 用某个办法应对 |
| 服务于 | 方法 | 归宿（价值或创作动机） | 办法服务于什么 |
| 排除 | 价值 | 排除的形态 | 这条价值排掉什么 |

串起来是一条链：**情境 →（情绪 →）办法 → 归宿**。`排除`挂在价值那一端，说清这条线不要什么。

## 有什么属性

记在条目上的四项：来源文件（`file`，条目出自哪份档案）、分组（`group`，只用于方法档案里的二级小节）、出处句（`quote`，档案里没有独立条目标题、只在句子里出现过的条目用它记原话）、参见（`seeAlso`）。

## 载体

每个集一份 `index.ttl`，各带自己的命名空间（`urn:quanttide-memory:<集>:profile:`）。本体与实例同住一份文件——类和四条关系是骨架，各个条目是实例。

## 三集之间

类名随集的主题替换，四条关系的语义不变。所以三份 TTL 不是三套本体，是**同一套本体的三个实例**。

两处差异：`fiction` 没有「情绪」和「表达」两格，情境直接接到办法；「排除」与「排除的形态」只出现在 `default` 与 `work`。
