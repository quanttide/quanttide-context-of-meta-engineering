## 1. 业务需求

人类提出的真实需求，不是「存几个文件」，而是**用结构化外化 + 计算审计，来达成靠通读做不到的自我认识**。需求在对话中逐步显影：

| 阶段 | 人类原话意图 | 真实业务需求 |
|—|—|—|
| ① 沉淀 | 把 profile 档案存成 ttl 并「理解它承载的知识」 | 把零散自省**从清单升级为可推理的图** |
| ② 好奇 | 「你有什么好奇的问题？会设计什么程序？」 | 让程序替自己**提出并验证自我假设** |
| ③ 验证 | 「先肉眼猜想，再用程序验证，记录进报告」 | 用**可计算证据**对抗通读印象（防自欺） |
| ④ 定位 | 「应该改进 ttl 还是改进程序？」 | 分清**数据缺口（真）vs 工具缺陷（伪）**——改的是认知内容，不是镜子 |
| ⑤ 标注 | 「你问我、我答，一个一个问」 | 用**苏格拉底式问答**，把审计暴露的孤节点逐条归并/补全 |

> 一句话：**一套可重复的个人认知审计方法**——把「自我模型」外置成 RDF，计算其结构缺陷，再用计算当镜子照见盲点。产物是 `*.ttl`（被照的模型）+ `audit.py`（镜子）+ 报告（照见的结果）。

## 2. 哲学意图

这里「本体」有**双重含义**，正是整套设计的哲学骨架：

- **本体论（ontology，RDFS 层）**：用 `rdfs:Class / subClassOf / domain / range` 形式化地定义「对象」与「态射」的种类与约束——这是工程侧的本体。
- **本体（noumenon，形而上学层）**：把「自我」不当成混沌整体，而建模为**对象（节点）+ 态射（有向关系）构成的范畴**——这是哲学侧的本体。自我被当作一个**范畴（category）**：对象是其元素，箭头是其运动方式。

四条态射构成一条**过程形而上学**的因果/意向链：

> 触发 `evokes` 情绪 → 情境 `responds_to` 方法 → 方法 `serves` 价值 → 价值 `excludes` 形态

两种认识路径并存：
- **_cataphatic_（肯定神学）**：`serves` 链——自我「追求什么」（积极定义）；
- **_apophatic_（否定神学）**：`excludes` 链——自我「不做什么」（通过否定定义）。审计发现 default 集只在经营域把排除轴显式编码，恰说明**此人的边界意识先于追求意识成型**。

最关键的一步哲学动作发生在标注会话：**「同源」聚类**。它做的是形而上学还原——把现象界看似杂多的 9 个困境，还原为**同一个 noumenon（「怕自己不够好」）的 9 张脸**。`rdfs:seeAlso` 在这里充当「弱同一/相似」关系，承认表象可分而本源为一。

## 3. 数学推理

核心是**带类型的有向多重图 + 定义在图上的度量函数**。

**① 图模型**
$$G=(V,E),\quad E\subseteq V\times P\times V,\quad P=\{\text{evokes, responds\_to, serves, excludes, seeAlso}\}$$

每个态射是**带类型的箭头**（范畴的态射签名），构成约束：

| 态射 | 签名 domain → range |
|—|—|
| evokes | Trigger → Emotion |
| responds_to | (Trigger ∪ Emotion ∪ Dilemma) → Method |
| serves | Method → (Value ∪ Motivation) |
| excludes | Value → Anti |

**② 核心度量（均为图上的函数）**

- 蒸馏成熟度：$\operatorname{dist}(S)=\dfrac{\lvert\pi(E)\cap S\rvert}{\lvert S\rvert}\in[0,1]$（$\pi$ 把边投影到端点节点；对象属性 file/quote/group 不计边）
- 边界/追求比：$\rho(S)=\dfrac{\lvert\text{excludes}\rvert}{\lvert\text{serves}\rvert}$
- 一致性缺口：$\operatorname{gap}(S)=\{v\in V:\operatorname{type}(v)\in\{\text{Value,Motivation}\}\land \neg\exists(v,\text{serves},\cdot)\in E\}$
- 应对集中度（熵）：$H=-\sum_i \frac{f_i}{F}\log_2\frac{f_i}{F}$（$f_i$ 为方法 $i$ 的 responds_to 入度；低熵=套路化）
- 恐惧无解法：$\operatorname{fear}(S)=\{v:\operatorname{orphan}(v)\land \operatorname{type}(v)\in\{\text{Emotion,Dilemma}\}\land \operatorname{label}(v)\text{ 含怕/不敢/焦虑…}\}$

**③ 同源等价关系（标注会话引入）**

定义 $R$ 为 `seeAlso` 在 Dilemma 上的传递闭包，得到困境的等价划分 $\mathcal{P}=V_{\text{Dilemma}}/R$。审计原假以为 $\lvert\mathcal{P}\rvert$ 很大（9 个碎片），实测发现**单一等价类占 8/9**——即多数表象收敛到一个根。

**④ 一个被程序 bug 揭示的「度量有效性定理」**
`localname` 必须按 `#` 再按 `:` 切分（兼容 `urn:…:x` 与 `http://…#x`）。若切错，会把**模式类/属性误算为实例**，使 $|S|$ 虚增、$\operatorname{dist}(S)$ 被压低——这证明：**度量函数必须在其真实定义域（实例集 ∖ 模式集）上计算，否则结果是伪值**。这恰是整套「用程序防自欺」主旨的数学注脚。

**总括**：业务上是「个人认知审计」，哲学上是「把自我建构成可推理的范畴、并用肯定/否定两条路径认识它」，数学上是一张**带类型的图 + 定义在图上的度量与等价关系**，代码上是**一组图度量函数 + 猜想验证对照**。三份 TTL 是被照的模型，`audit.py` 是镜子，而标注会话证明：镜子照出的最值钱的东西，往往是「你以为的碎片，其实是一个根的 many faces」。
