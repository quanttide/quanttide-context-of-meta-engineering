第一个版本不要验证“系统能不能用”，验证“结构对不对”。用最小可跑通的模型，把核心命题跑一遍，看结论是否符合直觉、是否可追溯、改动时是否自动一致。

验证目标

三个命题：

1. 参照系成立：创始人作为初始对象，所有主体从它可达，关系链可追溯。
2. 弱中心成立：主数据只共享主体和关系，领域规则可以独立变化，不影响全局视图。
3. 函子保持结构：至少一个业务领域接入后，跨领域查询结果与领域内推理一致。

最小模型

主体（5个）：创始人、量潮创新联盟、量潮科技、道江网络、量潮实训基地。

关系（6条）：

· 创始人 → 实际控制 → 联盟（依据：发起协议）
· 创始人 → 实际控制 → 量潮科技（依据：股权/控制协议）
· 创始人 → 实际控制 → 道江网络（依据：股权/控制协议）
· 联盟 → 托管 → 实训基地（依据：托管协议）
· 实训基地 → 提供服务 → 量潮科技（依据：服务合同A）
· 实训基地 → 提供服务 → 道江网络（依据：服务合同B）

一个领域接入：选“服务结算”作为第一个接入的领域。它只需要管：服务合同、派工记录、结算单。所有这些引用主数据里的主体ID和关系ID。

验证步骤

第一步：录入，跑一致性检查

录入5个主体、6条关系、4份协议。检查：

· 每个主体有唯一标识。
· 每条关系有源、目标、类型、生效日、依据协议。
· 控制关系不成环。
· 每份协议关联至少一条关系。

跑通后，问三个问题，看回答是否可追溯：

· “创始人控制哪些主体？” → 三个，每条附带控制协议。
· “实训基地给谁服务？” → 两个，每条附带服务合同。
· “创始人对实训基地的影响路径是什么？” → 创始人→联盟→基地，依据：控制协议+托管协议。

如果每条答案都能点回到具体协议，第一步通过。

第二步：加一条业务数据，验证弱中心

在服务结算领域录入一条派工记录：实训基地派了5个人到量潮科技，3月份，结算金额X。这条记录引用“实训基地→提供服务→量潮科技”这条关系ID。

然后改领域规则：假设原来结算按人头算，现在改成按项目算。改完后，重新查询“实训基地给谁服务”，答案不变——还是两个。再查“创始人控制哪些主体”，答案不变——还是三个。

这说明领域规则的变化没有污染主数据。弱中心成立。

第三步：换一条关系，验证函子保持结构

把“实训基地→提供服务→量潮科技”这条关系的服务合同从A换成B。主数据里只改关系的依据协议ID。

然后查服务结算领域：原来挂在这条关系下的派工记录和结算单，是否自动关联到新合同？如果系统按关系ID挂接，应该自动关联。如果按合同ID挂接，就需要手动迁移——这说明领域接入时函子映射没有保持结构。

这一条如果通过，说明函子确实保持了“关系→依据→业务数据”这条链的结构。

第四步：模拟一次真实变更，验证一致性自动保持

场景：创始人把道江网络的股权全部转让给联盟。

操作：在关系表里，把“创始人→实际控制→道江网络”标记失效，新增一条“联盟→实际控制→道江网络”，生效日设为转让日，依据协议设为股权转让协议。

然后问：

· “创始人现在控制哪些主体？” → 联盟、量潮科技（道江网络不再直接控制）。
· “联盟控制哪些主体？” → 道江网络。
· “创始人对道江网络还有影响吗？” → 有，路径：创始人→联盟→道江网络，依据：控制协议+股权转让协议。

如果这三个答案都正确，且都能点回协议，说明变更后结构一致性自动保持。范畴论里，这是推出（pushout）在具体数据上的效果：旧关系失效，新关系加入，推理引擎自动重算所有可达路径。

验证通过的标准

· 五个主体的所有关系链可追溯至具体协议。
· 领域规则变化后，主数据视图不变。
· 换协议后，业务数据自动跟随关系ID重新挂接。
· 一次控制权变更后，所有相关查询结果自动一致，无需手动修数据。

这四条都过，第一个版本就验证完了。接下来可以接入第二个领域，或者扩展主体和关系类型。如果某条没过，问题出在函子映射或公理定义上，范畴论分析已经帮你定位了具体位置。
